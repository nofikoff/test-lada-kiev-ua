# Implementation Plan: Визуальный редизайн шаблона страниц

**Branch**: `002-visual-redesign` | **Date**: 2026-09-06 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/002-visual-redesign/spec.md`

## Summary

Перенос вёрстки из пакета 001 был сделан один в один — это было условие проверяемости миграции, и оно же законсервировало оформление 2023 года: два неразличимых чёрных фона, одна композиционная ось, один вертикальный отступ на все секции, отсутствие типографической шкалы и движения.

Работа вводит слой дизайн-токенов и собирает из него оформление заново. Палитра переходит на тёплый уголь с латунью, уровни текста становятся тремя именованными вместо семи произвольных прозрачностей белого, заголовочная гарнитура меняется на более контрастную, вертикальный ритм получает четыре ступени вместо одной. Поверх появляется motion-слой целиком на CSS: сквозной фон из света, линий, частиц и зерна, раскрытие первого экрана, мерцание латуни, проявление блоков при въезде в кадр.

Ключевое решение по проверяемости: три новых автоматических проверки — контраст всех пар палитры, длина строки на страницах категорий, полная неподвижность при системном запросе уменьшенного движения. Ровно эти три величины нельзя увидеть на скриншоте, и ровно они молча деградируют при следующей правке стилей: недобор контраста в подвале, попавший в итоги пакета 001, доказывает это на самом проекте.

## Technical Context

**Language/Version**: TypeScript 5.5, Node ≥ 22.12 — состав не меняется, стек унаследован от пакета 001

**Primary Dependencies**: Astro 7.3.1 (`output: 'static'`), Tailwind 3.4 через `postcss.config.js`, `@astrojs/sitemap` 3.7.4, Astro Fonts API. Новых зависимостей работа не вносит: анимация, токены и фоновый слой — стандартный CSS

**Storage**: без изменений — прайс в JSON, тексты категорий в Markdown, подписи интерфейса в типизированном модуле. Работа добавляет в словарь новые подписи (надзаголовки контактов и инструментов), обязательные во всех трёх локалях

**Testing**: Playwright против собранного сайта, семь существующих файлов проверок плюс три новых (контраст, длина строки, уменьшенное движение); `astro check`; `scripts/analyze-bundle.mjs` как страж бюджета исполняемого кода; `scripts/test-invalid-data.mjs` без изменений

**Target Platform**: статические файлы на Apache. Приёмка — движки Chromium и WebKit автоматически, Gecko одним ручным проходом (SC-013)

**Project Type**: статический многоязычный сайт, 15 публичных страниц плюс страницы ошибок

**Performance Goals**: пороги пакета 001 не проседают — LCP ≤ 2.5 с, CLS < 0.1, производительность ≥ 95, поисковая оптимизация 100; доступность поднимается с 96 до 100

**Constraints**: исполняемый код помимо аналитики не растёт относительно 732 Б (замер `npm run analyze`); анимация только на `transform` и `opacity`; весь видимый текст сохраняется дословно; адреса, метаданные, карта сайта и правила сервера неизменны; идентификаторы и роли вкладок прайса и мобильного меню сохраняют контракт (`tests/interaction.spec.ts`)

**Scale/Scope**: 8 существующих компонентов к пересборке, 4 новых примитива, 1 файл стилей, 1 файл конфигурации Tailwind, 1 конфигурация прогона, 3 новых файла проверок, ~12 новых строк словаря × 3 локали

## Constitution Check

*GATE: пройден до Phase 0, перепроверен после Phase 1.*

| Принцип | Оценка | Обоснование |
|---------|--------|-------------|
| I. Zero client-side framework | ПРОЙДЕН | Ни одной новой строки исполняемого кода: фон, мерцание, раскрытие и проявление — CSS. Уплотнение шапки и проявление блоков делаются анимациями, привязанными к прокрутке, вместо наблюдателя пересечений, который стоил бы ~400 Б и нарушил бы работу без скриптов. Стражем служит `npm run analyze`, порог — нынешние 732 Б, а не потолок в 5 КБ |
| II. Контент — это данные | ПРОЙДЕН | Новые подписи входят в тот же типизированный словарь; отсутствие ключа в любой локали — ошибка компиляции, а не пустое место. Ни одна строка не появляется в разметке компонента |
| III. URL — публичный контракт | ПРОЙДЕН | Работа не касается маршрутов, `.htaccess`, карты сайта и канонических адресов. Проверки `tests/routes.spec.ts` и `tests/sitemap.spec.ts` остаются эталоном |
| IV. Страница самодостаточна | ПРОЙДЕН | Метаданные и машиночитаемое описание не меняются. Единственное касание — логотип: он уходит из вёрстки, но остаётся изображением организации в описании (уточнение сессии 2026-09-06), поэтому `tests/seo-contract.spec.ts` продолжает проходить без правок |
| V. Готовность доказывается прогоном | ПРОЙДЕН | Каждый критерий приёмки имеет команду в [quickstart.md](./quickstart.md). Три величины, которые раньше принимались на глаз, переводятся в автоматические проверки |

**Замечание к разделу технических ограничений конституции.** Конституция запрещает совмещать смену мажорной версии Tailwind с переносом вёрстки. Здесь переноса нет, но есть переработка оформления — и соблазн заодно поднять Tailwind до 4, где токены на CSS-переменных нативны, велик ровно по той же причине, по которой это запрещено: расхождение в отображении стало бы невозможно отнести к причине. Версия остаётся третьей, токены заводятся через формат `rgb(var(--x) / <alpha-value>)`, поддерживаемый с Tailwind 3.1 ([research.md §R4](./research.md)). Подъём мажорной версии — отдельный пакет, и эталоном сверки для него служат снимки, принятые здесь.

**Structure Decision**: слой примитивов, а не правка утилит по месту. Причина измерима: `py-20 md:py-32` сегодня продублирован в восьми компонентах, а `section-title` задаёт один кегль всем заголовкам независимо от объёма секции. Пока ритм и роли живут в разметке каждого компонента, любая правка ритма — это восемь одинаковых правок, и рассинхрон между ними ничем не запрещён. Примитив `Section` делает роль секции параметром, `SectionHeading` — парой «надзаголовок + заголовок», и оба читаются в одном месте.

Файл `src/styles/ambience.css` отделён от `index.css` намеренно: фоновый слой — единственная часть работы, которую при откате нужно снять целиком, не трогая палитру и шкалу. Разделение делает откат одной строкой импорта.
