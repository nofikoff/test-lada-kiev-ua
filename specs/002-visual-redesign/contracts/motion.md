# Контракт: слои движения

Периоды даны для зашитого уровня — того, что владелец выбрал на прототипе как «полный». Регулятора интенсивности на сайте нет (уточнение сессии 2026-09-06): значения фиксированы.

## Состав

| Слой | Период | Что анимируется | Где |
|---|---|---|---|
| `glow` × 4 | 17 / 23 / 29 с, часть в противофазе | `transform`, `opacity` | сквозной фон |
| `silk` × 2 | 34 и 46 с | `transform` (сдвиг, масштаб, скос) | сквозной фон |
| `lamp` | 11 с | `opacity` | сквозной фон |
| `mote` × 20 | 22–40 с, каждая своя | `transform`, `opacity` | сквозной фон и первый экран |
| `grain` | 6 с, шагами | `transform` | сквозной фон |
| `wake` | 1.8 с, однократно | `opacity` | затемнение первого экрана |
| `drift` | 32 с | `transform` | кадр первого экрана |
| `veil-breath` | 13 с, после `wake` | `opacity` | затемнение первого экрана |
| `shimmer` | 5–7 с, задержки вразброс | `transform` | латунные волоски, кнопка, рамка карточки |

| `reveal` | по таймлайну кадра | `transform`, `opacity` | секции и карточки |

## Жёсткие правила

1. **Только композируемые свойства.** Анимируются `transform` и `opacity`. Исключение одно — `ember` на `text-shadow`: он не двигает раскладку, применён к строкам в 3–5 слов и заменяет собой свечение, которое иначе потребовало бы отдельного слоя под каждым надзаголовком.
2. **Ноль исполняемого кода.** Ни одна анимация не требует скрипта. Проверяется `npm run analyze`: ожидаемое значение — 732 Б, как до работы.
3. **Подложка под текстом первого экрана неподвижна** (FR-017). Дышит только затемнение над кадром; слой под текстовой колонкой в анимациях не участвует ни при каких условиях.
4. **Невидимость живёт внутри `@supports`.** Правильный порядок вложенности:

```css
@media (prefers-reduced-motion: no-preference) {
  @supports (animation-timeline: view()) {
    .reveal { animation: reveal linear both; animation-timeline: view(); }
    @keyframes reveal { from { opacity: 0; transform: translateY(14px); } }
  }
}
```

Обратный порядок — `opacity: 0` в базовом правиле и снятие его анимацией — оставляет блок невидимым навсегда там, где таймлайн не поддержан. Это единственная ошибка в этой работе, которая выглядит как пустая страница.

5. **Уменьшенное движение выключает всё.**

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation: none !important; transition: none !important; }
  html { scroll-behavior: auto; }   /* иначе плавная прокрутка переживает отключение анимаций */
}
```

Конечные состояния при этом обязаны быть видимыми — что и гарантирует правило 4.

Строка про прокрутку не декоративна: `scroll-behavior: smooth` объявлен глобально в `index.css:6-8` и не является ни анимацией, ни переходом, поэтому правило выше его не гасит. Переход по внутренней ссылке остался бы плавным именно у тех, кто попросил обратного.

6. **Частота изменений яркости — не чаще трёх в секунду** (FR-015a). Самый быстрый слой в наборе имеет период 3.6 с, так что запас двукратный с лишним; правило существует, чтобы его не потеряли при следующей правке темпа.

## Границы поддержки

`animation-timeline: view()` и `scroll()`: Chrome 115+, Safari 26+, Firefox 158+ — 87.22% посетителей (caniuse, проверено 2026-09-06). Остальные видят страницу без проявления блоков и с постоянно плотной шапкой. Это штатное поведение, а не дефект: SC-012 требует именно его.

`initial-letter` (буквица): Chrome 110+ и Safari 9+ частично, Firefox не поддерживает; 91.66%. Без поддержки абзац начинается обычной буквой.

## Что проверяется автоматически

- Полная неподвижность при `prefers-reduced-motion: reduce` — `tests/reduced-motion.spec.ts` (SC-007).
- Отсутствие прироста исполняемого кода — `npm run analyze` (SC-005).
- Читаемость первого экрана независимо от фазы анимации — часть `tests/contrast.spec.ts` (SC-001).

Что не проверяется автоматически и остаётся ручным проходом: субъективная уместность темпа, работа жестов внутри карты под фильтром в WebKit (research.md §R10), целостность страницы в Firefox без проявлений (SC-013).
