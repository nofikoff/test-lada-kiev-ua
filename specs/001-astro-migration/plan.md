# Implementation Plan: Статический многоязычный сайт вместо клиентского SPA

**Branch**: `001-astro-migration` | **Date**: 2026-09-06 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/001-astro-migration/spec.md`

## Summary

Действующий сайт — клиентское одностраничное приложение: сервер отдаёт пустой каркас, весь текст рисуют 224 КБ скриптов. Поисковые системы и соцсети содержимого не видят, метаданные общие на три языка, указаний языковых версий и машиночитаемого описания нет вовсе.

Сайт переводится на статическую генерацию: каждая страница каждого языка становится готовым HTML-файлом с собственными метаданными. Клиентский фреймворк снимается полностью — два интерактивных элемента реализуются средствами платформы. Контент выносится из разметки в проверяемые данные, и поверх той же модели добавляются двенадцать страниц категорий услуг.

Ключевое решение по проверяемости: перед удалением старого словаря переводов снимается эталонная фикстура всех его строк, и полнота переноса проверяется машинно, а не просмотром страниц.

## Technical Context

**Language/Version**: TypeScript 5.5, Node ≥ 22.12 (требование Astro 7.3.1, проверено `npm view astro@7.3.1 engines`; в системе 22.17.1)

**Primary Dependencies**: Astro 7.3.1 (`output: 'static'`, `build.format: 'directory'`), `@astrojs/sitemap` 3.7.4 (`site: 'https://www.lada.kiev.ua'`), Tailwind 3.4 с интеграцией `@astrojs/tailwind` 6.0.2, `astro:assets`, Astro Fonts API. Клиентского UI-фреймворка нет.

**Storage**: файлы в репозитории. Прайс — JSON через загрузчик `file()`, тексты категорий — Markdown через `glob()`, подписи интерфейса — типизированный модуль. Базы данных нет.

**Testing**: Playwright для сквозных проверок против собранного сайта, отдельный скрипт сверки полноты контента, `astro check` для типов, валидация коллекций при сборке.

**Target Platform**: статические файлы на Apache, ручная выкладка. Серверного выполнения кода нет.

**Project Type**: статический многоязычный сайт, 15 публичных страниц (3 языковые версии главной + 12 страниц категорий) плюс страницы ошибок.

**Performance Goals**: отображение основного содержимого первого экрана не позже 2,5 с на мобильном профиле; накопленный сдвиг макета ниже 0,1; исполняемый код помимо аналитики не более 5 КБ (сегодня 224 КБ).

**Constraints**: действующие адреса не меняются; вёрстка переносится один в один; поведение аналитики не меняется; мажорная версия Tailwind в рамках этой работы не поднимается.

**Scale/Scope**: 7 компонентов к переносу, ~60 позиций прайса в 11 группах, 3 локали, 12 новых текстов по ~400 слов, 1400 строк действующего кода к замене.

## Constitution Check

*GATE: пройден до Phase 0, перепроверен после Phase 1.*

| Принцип | Оценка | Обоснование |
|---------|--------|-------------|
| I. Zero client-side framework | ПРОЙДЕН | Меню — нативный элемент раскрытия, вкладки — скрипт компонента без зависимостей. React, маршрутизатор, библиотека иконок и неиспользуемый клиент базы данных удаляются. Проверяется измеримо: FR-029 ограничивает исполняемый код 5 КБ |
| II. Контент — это данные | ПРОЙДЕН | Три источника контента, ни один не в разметке. Схема требует все три локали; неполный перевод останавливает сборку (FR-023) |
| III. URL — публичный контракт | ПРОЙДЕН | Адреса сохранены, зафиксированы таблицей в [contracts/routes.md](./contracts/routes.md). Внимания требует одно: сборка каталогами даёт форму со слешем, действующие `/ru` и `/en` приходят к ней постоянным перенаправлением сервера — адрес не теряется, но канонический обязан указывать на форму со слешем |
| IV. Страница самодостаточна | ПРОЙДЕН | [contracts/page-head.md](./contracts/page-head.md) задаёт обязательный состав, проверка идёт по собранному HTML |
| V. Готовность доказывается прогоном | ПРОЙДЕН | Каждый критерий приёмки имеет команду в [quickstart.md](./quickstart.md); отправная точка измерений снимается до начала работ |

**Замечание к разделу технических ограничений конституции**: связка Tailwind 3 с интеграцией `@astrojs/tailwind` описана в документации Astro как режим совместимости с устаревшей версией. Это осознанно вносимая унаследованная зависимость. Конституция прямо запрещает совмещать смену мажорной версии Tailwind с переносом вёрстки, поэтому нарушения нет — но зависимость временная, и [research.md](./research.md) фиксирует условие её снятия: отдельный пакет сразу после приёмки, где эталоном сверки служат скриншоты, принятые здесь.

**Structure Decision**: один проект, без разделения на клиент и сервер — серверной части нет. Страницы разложены физическими каталогами локалей, а не динамическим параметром: при основном языке без префикса он всё равно живёт отдельным файлом, и параметр дал бы две разные механики для трёх одинаковых по смыслу страниц. Компоненты, наоборот, локали не знают — принимают её как входное значение, поэтому вёрстка существует в одном экземпляре.

Удаляются: `src/App.tsx`, `src/main.tsx`, `src/components/*.tsx`, `src/i18n/translations.ts` и `src/i18n/index.ts`, `index.html`, `vite.config.ts`, `postcss.config.js`. Словарь переводов удаляется **только после** снятия эталонной фикстуры.
