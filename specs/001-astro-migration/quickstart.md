# Quickstart: проверка миграции

Как убедиться, что миграция сделана правильно. Все проверки идут против **собранного сайта**, а не против исходников: требования спеки сформулированы про опубликованный файл.

## Предусловия

- Node ≥ 22.12 (`node -v`).
- Отправная точка измерений снята с действующего сайта **до** начала работ — см. «Замер отправной точки» ниже. Без неё критерии SC-004 и SC-005 непроверяемы.
- Эталонная фикстура `tests/fixtures/legacy-content.json` снята со старого словаря переводов до его удаления.

## Замер отправной точки (выполняется первым, до любых изменений)

Замер снимается с работающего прода `https://www.lada.kiev.ua`, а не с локальной сборки. Причина двойная: локальная сборка перестанет собираться уже на первом шаге установки Astro, а эталоном для сравнения является ровно то состояние, которое видит посетитель и поисковик — вместе с сетью доставки контента перед ним.

Снять и сохранить в `specs/001-astro-migration/baseline/`:

- отчёт аудита производительности на мобильном профиле для `/`, `/ru`, `/en` — медиана трёх прогонов на адрес, один прогон шумит на десятки пунктов;
- размер передаваемого исполняемого кода на странице;
- скриншоты трёх страниц в трёх ширинах экрана: 375, 768, 1440.

Эти файлы — единственное, с чем потом сравнивается результат. Снятые после начала работ, они уже ничего не доказывают.

## Ежедневный цикл

```bash
npm run dev            # разработка
npm run check          # типы, включая полноту словаря интерфейса
npm run build          # сборка с валидацией коллекций
npm run preview        # просмотр собранного сайта
```

Сборка обязана падать, если в данных прайса не хватает перевода или файл текста категории отсутствует. Это не побочный эффект, а требование FR-023.

## Приёмочные проверки

### 1. Полнота переноса контента (SC-001, FR-004)

```bash
npm run test:content
```

Сверяет каждую строку эталонной фикстуры с HTML соответствующей языковой версии. Провал означает потерянный при переносе текст — точное место указывает вывод.

Проверка остаётся в проекте навсегда: она же ловит потерю блока при любой последующей правке.

### 2. Контракт заголовочной части и адресов (FR-001, FR-002, FR-009 … FR-015, FR-021)

```bash
npm run test:e2e
```

Прогоняет по всем пятнадцати страницам проверки из [contracts/page-head.md](./contracts/page-head.md) и [contracts/routes.md](./contracts/routes.md): уникальность заголовков, канонические адреса, языковые альтернативы, коды ответа, страница ошибки на нужном языке.

### 3. Машиночитаемое описание (FR-011, FR-012)

Автоматическая часть входит в тот же прогон: разбор разметки, число предложений, отсутствие нулевых цен.

Ручная часть — прогон трёх страниц (главная, страница категории с вариантами длительности, страница категории с долевыми ценами) через валидатор структурированных данных. Вывод валидатора прикладывается к приёмке.

### 4. Поведение интерфейса (FR-027, FR-028)

Входит в сквозной прогон: открытие и закрытие меню, переключение вкладок мышью и клавишами со стрелками, корректность объявляемого состояния.

Отдельно проверяется отключение скриптов в браузере: весь прайс должен остаться видимым. Если при отключённых скриптах не видно ни одной вкладки — начальное состояние разметки сделано неверно (см. R10 в [research.md](./research.md)).

### 5. Вес и скорость (SC-004, SC-005, SC-006)

```bash
npm run build && npm run analyze
```

Суммарный размер исполняемого кода помимо аналитики — не более 5 КБ. Затем аудит производительности на мобильном профиле по тем же трём адресам, что в отправной точке, и сравнение с ней.

### 6. Сверка отображения

Скриншоты новой сборки в тех же трёх ширинах экрана против отправной точки. Сверяется глазами: попиксельного совпадения не требуется — шрифты теперь отдаются с собственного домена и могут дать иные метрики, — но состав, порядок и оформление блоков обязаны совпадать.

Расхождение считается дефектом переноса, а не улучшением: изменения дизайна в объём работы не входят.

### 7. Проверка на испорченных данных (SC-010)

```bash
npm run test:invalid-data
```

Три случая порчи, каждый ожидает ненулевой код возврата сборки: отсутствующий перевод названия позиции, отсутствующий файл текста категории, отрицательная цена. Порча вносится во временную копию и откатывается автоматически.

Автоматической эта проверка сделана намеренно. Ручная процедура «сломать, посмотреть, откатить» проверяет схему один раз в жизни — в тот день, когда её написали; после первого же расширения схемы никто её не повторит, и требование FR-023 останется утверждением без подтверждения.

**Подтверждено 2026-09-06** (Step 6.1, T052). Три случая, код возврата сборки 1 у каждого, сообщение называет поле:

```
✓ отсутствующий перевод названия позиции: name.ru: Required
✓ отсутствующий файл текста категории:    Error: нет текста услуги: src/content/services/uk/massage.md
✓ отрицательная цена:                     price.amount: Too small: expected number to be >0
```

Второй случай ловится не схемой, а страницей, которая текст запрашивает: схема проверяет то, что есть, а нарушение состоит в отсутствии файла. Прогон заканчивается сборкой на восстановленном дереве, поэтому `dist/` после него годен для остальных проверок.

### 8. Правка цены в одном месте (FR-022, User Story 4)

Цена меняется в `src/data/prices.json` и больше нигде: второй записи цен в проекте нет.

**Подтверждено 2026-09-06** (Step 6.1, T053). Позиция `women-depilation-underarms` переведена с 400 на 437 грн, `npm run build`, после сверки возвращена обратно. Новое значение появилось во всех шести местах отображения:

| Страница | Прайс | Разметка предложений |
|----------|-------|----------------------|
| `/`, `/ru/`, `/en/` | 437 грн / 437 UAH | предложений нет по контракту |
| `/depilation/`, `/ru/depilation/`, `/en/depilation/` | 437 грн / 437 UAH | `"price":437` |

Ценовой диапазон главной страницы правкой не затронут: 437 не крайнее значение прайса.

## Перед публикацией

- [ ] Тексты двенадцати страниц категорий вычитаны владельцем.
- [ ] Кириллица в декоративном шрифте проверена рендером украинского заголовка (см. R8).
- [ ] Изображение предпросмотра весит не больше 300 КБ и открывается по постоянному адресу.
- [ ] Файл правил для роботов и карта сайта отвечают кодом 200 и ссылаются друг на друга.
- [ ] Предыдущая сборка сохранена: откат — это публикация её обратно.

## После публикации

- Карта сайта отправлена в поисковую консоль.
- Просмотрен отчёт об ошибках сканирования: адреса, ранее отвечавшие успехом из-за подстановки главной страницы, теперь дают 404. Настоящие битые ссылки среди них требуют перенаправлений.
