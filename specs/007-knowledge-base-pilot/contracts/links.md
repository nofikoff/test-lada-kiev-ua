# Contract: Links

Какие ссылки появляются на странице и откуда берётся их текст. Источник — `docs/seo/map.md` §Links, пишет его `/seo map`; почему сборка читает карту, а не копию — [research.md](../research.md) R3. При реализации переносится в [docs/specs/routes.md](../../../docs/specs/routes.md).

## Rule

Ребро `from → to (lang)` выводится на странице `from` языка `lang`, когда страница `to` этого языка собрана. Опубликованной страницу делает файл в контенте, а не `status` карты. Ссылка — адрес `to` из §Pages со слешем; текст — анкор, приведённый `displayAnchor`. После trim, схлопывания пробелов и нижнего регистра текст равен анкору карты.

## Placement

| Страница | Что выводится | Где |
|---|---|---|
| категория, подстраница | рёбра к страницам базы знаний (`hub`, `entity`, `question`) | `MapLinks` сразу после `.service-copy`, вне `[data-service-copy]`; рёбер к собранным страницам нет — блока нет |
| хаб | список статей своей категории и языка: все статьи из коллекции, текст — анкор ребра «хаб → статья»; порядок — `published` по убыванию, затем `heading` | тело хаба после вступления |
| хаб | остальные рёбра (к услуге) | `MapLinks` после списка |
| статья | все рёбра (к хабу, к услуге, к сравнению шугаринга и т. п.) | `MapLinks` после текста |
| статья | подпись: `signatureName`, `signatureRole` из `src/content/about/<lang>.md` → страница эксперта своего языка | под `<h1>`, с датами публикации и правки |
| статья | крошки «главная → хаб → статья», имена — `nav.home` и `heading` | над `<h1>` |
| хаб | крошки «главная → хаб» | над `<h1>` |
| эксперт | список всех статей своего языка, текст — `heading` статьи, с датой публикации | после текста |

Ребро «хаб → статья» обязано быть в карте для каждой статьи, иначе сборка останавливается ([content-files.md](content-files.md) §Build stops, № 11). Так хаб перечисляет все статьи и ни одну без анкора карты.

## Not linked

- Шапка сайта не меняется: пункта раздела в навигации нет.
- Ни одна ссылка блока, списка или подписи не ведёт на несобранный адрес. Ссылки, которые автор ставит в теле Markdown, проверяются тем же тестом и тоже обязаны стоять в форме со слешем: `/depilation` указывает на перенаправление и тест его не принимает.
- Статус страницы в карте на вывод не влияет: ссылку на страницу `planned` сборка выводит, если её файл есть в контенте, и не выводит ссылку на страницу `published` без файла.
