# Contract: Content Files

Интерфейс автора статьи: что положить в репозиторий, чтобы страница вышла, и чем сборка отвечает на ошибку. При реализации переносится в [docs/specs/content-model.md](../../../docs/specs/content-model.md) §Knowledge base.

## Layout

```text
src/content/guide/<lang>/<category>.md            → хаб    /<prefix>guide/<category>/
src/content/guide/<lang>/<category>/<article>.md  → статья /<prefix>guide/<category>/<article>/
src/content/expert/<lang>.md                      → эксперт /<prefix>lada/
```

`<lang>` — `uk` или `ru`, `<prefix>` — пусто для uk, `ru/` для ru. Версии одной страницы на двух языках — два файла с одинаковым путём под разными `<lang>` и одинаковым `page`.

## Frontmatter

```yaml
# guide
page: depilation-vs-epilation     # page из docs/seo/map.md §Pages
title: "… — Lada N"               # ≤ 70 знаков
description: "…"                  # 120–160 знаков
heading: "…"                      # <h1>
published: 2026-10-20             # не меняется после выхода
modified: 2026-10-20              # двигает изменение смысла, не опечатка; ≥ published
```

```yaml
# expert
title: "Лада Новикова: … — Lada N"  # ≤ 70 знаков
description: "…"                  # 120–160 знаков, содержит «Лада Новикова»
heading: "Лада Новикова"
```

Других ключей нет; `slug` запрещён (research R1). Флага черновика нет: черновик — `docs/seo/drafts/`, в сборку не попадает.

Даты:

- `modified` равна `published` у новой статьи — допустимо.
- Дату в будущем сборка не ловит: проверка с текущей датой сделала бы исход сборки зависимым от дня запуска. Её ловит вычитка.
- У пилота обе даты — день слияния ветки в `main`; ставятся последним коммитом ветки перед слиянием, в день слияния. Публикация идёт в тот же день, по словам автора, поэтому дата на странице совпадает с днём выхода на сайт. Слияние переехало на другой день — даты ставятся заново, а не остаются от прогона реализации.

## Text rules

| Страница | Правило | Держит |
|---|---|---|
| статья | основная формулировка кластера в `title`, `heading`, `description` (в первой половине) и первом абзаце тела | `tests/voice.spec.ts` |
| статья | ≥ 400 слов в `[data-guide-copy]`, абзацы не повторяют другие страницы своего языка | `tests/seo-contract.spec.ts` |
| хаб | `title` и `heading` называют раздел базы знаний и категорию по формуле [page-head-and-jsonld.md](page-head-and-jsonld.md) §Head | `tests/voice.spec.ts` |
| хаб | в `title`, `heading`, `description` нет формулировок запросов категории (`page-head.md` §Целевые запросы) и запросов его статей; слово категории допустимо; проверка «запрос в первой половине описания» у хаба не выполняется — запроса у него нет | `tests/voice.spec.ts` |
| эксперт | «Лада Новикова» в `title`, `heading`, `description`; третье лицо; только факты FR-008; ни один абзац не совпадает с «Про нас» своего языка | `tests/voice.spec.ts`, `tests/seo-contract.spec.ts`, вычитка |
| все | «ми» студии, Лада — в третьем лице; все услуги студии Лада выполняет сама, при большом потоке клиентов ей помогают мастера (spec FR-014); запреты `voice.md` | вычитка; «майстерня» — `tests/voice.spec.ts` |
| статья | общее утверждение — с источником в таблице источников; практика студии — только `studio-practice.md`, прайс, текст категории | вычитка |
| хаб | вступление — от «ми», в `[data-guide-copy]`; нижней границы объёма нет — хаб служит списком; абзацы не повторяют другие страницы своего языка | `tests/seo-contract.spec.ts`, вычитка |
| статья | личный опыт Лады из `studio-practice.md` («мне например») передаётся нейтральной формой «некоторым клиентам…»: текст говорит от «ми», подпись не делает его первым лицом Лады | вычитка |
| все | ссылка в теле Markdown — на собранный адрес в форме со слешем | `tests/links.spec.ts` |

### Claim kinds

| Вид | Что это | Источник |
|---|---|---|
| общее утверждение | факт о методе вне студии: что разрушает фолликул, сколько держится результат, как называется метод | внешний источник, строка в research.md §Sources |
| практика студии | что делает студия: материал, зоны, срок повторного визита, чего в студии нет | `studio-practice.md`, `src/data/prices.json`, действующий текст категории |
| описание техники | как проходит процедура без утверждений о студии и без чисел | ответа Лады не требует ([content-model.md](../../../docs/specs/content-model.md) §Service subpage); число или срок делают его общим утверждением |

Любой другой факт — стаж, курсы, сертификаты — появляется на странице только с ответом Лады из spec §Lada's Facts и строкой в этой таблице.

## Build stops

Нормативная детализация spec FR-004. Проверки идут в этом порядке; первая сработавшая останавливает сборку, и её сообщение называет файл. Тексты — образец, `test:invalid-data` сверяет выделенную часть.

| # | Нарушение | Где | Сообщение |
|---|---|---|---|
| 1 | `modified` раньше `published` | схема | ошибка схемы записи `guide → <id>` по полю **`modified`** |
| 2 | неизвестный ключ frontmatter, описание вне 120–160 | схема | ошибка схемы записи с именем поля |
| 3 | путь не `<lang>/<category>.md` и не `<lang>/<category>/<article>.md`, slug не латиница через дефис | `guide.ts` | `<filePath>: путь не хаба и не статьи базы знаний` |
| 4 | `<lang>` не `uk`/`ru` | `guide.ts` | `<filePath>: язык «<lang>» в базе знаний не публикуется` |
| 5 | `<category>` не из `serviceCategories` | `guide.ts` | `<filePath>: категории «<category>» нет` |
| 6 | повтор `page` в пределах языка | `guide.ts` | `<filePath> и <filePath>: page «<page>» повторяется в языке <lang>` |
| 7 | один `page` на разных языках лежит по разным путям, или один путь на разных языках несёт разные `page` | `guide.ts` | `<filePath> и <filePath>: версии страницы «<page>» лежат по разным адресам` |
| 8 | статья без хаба своего языка | `guide.ts` | `<filePath>: нет хаба src/content/guide/<lang>/<category>.md` |
| 9 | хаб без статьи своего языка | `guide.ts` | `<filePath>: у хаба нет ни одной статьи языка <lang>` |
| 10 | `page` нет в карте для этого языка или адрес в карте другой | `guide.ts` | `<filePath>: page «<page>» (<lang>) в docs/seo/map.md §Pages <нет \| с адресом <url>>, файл даёт <path>` |
| 11 | у статьи нет ребра «хаб → статья» в карте | `guide.ts` | `<filePath>: в docs/seo/map.md §Links нет строки <hub> → <page> (<lang>)` |
| 12 | в карте нет §Pages или §Links или нужной колонки | `seo-map.ts` | `docs/seo/map.md: <что не найдено>` |
| 13 | нет файла эксперта языка | `expert.ts` | `нет текста страницы эксперта: src/content/expert/<lang>.md` |

Остановка № 12 срабатывает первой из остановок, связанных с картой: `guide.ts` читает и разбирает `docs/seo/map.md` после проверок 3–9 и до № 10, и `parseSeoMap` бросает № 12 при чтении. Сверять файлы с картой, которую не удалось разобрать, нечего. Номер 12 в таблице — нумерация, а не очередь.

Правило 7 стоит перед проверками карты: версии сопоставляются по общему адресу (ADR-008), и страница на двух адресах дала бы две одноязычные страницы без пары `hreflang` — сборка прошла бы молча. Остановки 10–12 срабатывают и на публикации цен Лады: сборка читает карту из `main`. Что делать, если публикация упала по ним, — `docs/runbook-deploy.md` (plan.md §Structure Decision, документы при реализации).
