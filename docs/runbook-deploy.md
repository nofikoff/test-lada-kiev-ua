# Выкладка lada.kiev.ua

Сайт — статические файлы из `dist/`, выкладываемые вручную на Apache за сетью доставки контента. Порядок шагов ниже обязателен: сеть доставки стоит перед сервером, а файлы предыдущей сборки, оставленные на нём, продолжают отвечать кодом 200 ([docs/specs/routes.md](specs/routes.md)).

## Перед выкладкой

```bash
npm run check
npm run build
npm run test:content
npm run test:e2e
npm run test:invalid-data
```

Красный `test:content` означает потерянный текст и останавливает выкладку. Остальные — тоже, но этот единственный ловит потерю, которую на глаз не видно.

Красный `tests/build-output.spec.ts` внутри `test:e2e` значит, что в выдачу попал комментарий кода; правило — [конституция](../.specify/memory/constitution.md) §Quality Gates.

Сохранить архив текущей рабочей сборки с сервера: откат — это выкладка её обратно, другого механизма нет.

## Выкладка

1. **Удалить файлы предыдущей сборки** с сервера — весь корень сайта, кроме того, что туда не кладёт сборка. Оставленные, они отвечают кодом 200 и остаются в индексе как дубли.
2. **Выложить `dist/` целиком.** Вместе с ним уезжают три файла `.htaccess`: корневой, `ru/.htaccess` и `en/.htaccess` — именно они задают страницу ошибки на языке раздела. Проверить, что клиент выкладки не отфильтровал файлы, начинающиеся с точки: это его поведение по умолчанию, и без них сайт отдаёт SPA-подобный 200 на любой битый адрес.
3. **Сбросить кэш сети доставки** ровно для того, у чего адрес постоянный: HTML всех пятнадцати страниц, `/robots.txt`, `/llms.txt`, `/sitemap-index.xml`, `/sitemap-0.xml`. Файлы `_astro/*` сброса не требуют — их имена содержат хэш содержимого. Изображение предпросмотра ссылок теперь среди них: оно собирается из портрета и меняет адрес вместе с картинкой ([docs/specs/home-hero.md](specs/home-hero.md) §Превью ссылок и JSON-LD).

Статика кэшируется сетью доставки четыре часа (измерено 2026-09-06), поэтому без шага 3 правка `robots.txt` или карты сайта дойдёт до роботов не сразу. HTML на её стороне не кэшируется — страницы видны немедленно.

## После выкладки

```bash
curl -sI https://www.lada.kiev.ua/nonexistent-check | head -1     # 404, не 200
curl -s  https://www.lada.kiev.ua/robots.txt                      # наш файл, см. ниже
curl -sI https://www.lada.kiev.ua/sitemap-index.xml | grep -i type # application/xml
curl -s  https://www.lada.kiev.ua/en/nonexistent-check | grep -o 'lang="[a-z]*"' | head -1
```

- **Файл правил для роботов обязан быть нашим.** До миграции его отдавала сама сеть доставки, поскольку в проекте файла не было; признак нашего — строка `Sitemap: https://www.lada.kiev.ua/sitemap-index.xml`. Чужой файл означает, что сброс кэша не дошёл до этого адреса.
- **Язык страницы ошибки по разделу** (`lang="en"` в последней команде) — единственная строка контракта адресов, которую локальный сервер предпросмотра проверить не может: `ErrorDocument` внутри каталога он не реализует. Проверяется здесь и только здесь.
- Адреса `/ru` и `/en` без завершающего слеша обязаны приходить на форму со слешем постоянным перенаправлением: на них стоят внешние ссылки.
- Файлы предыдущей сборки более не отвечают кодом 200 — выборочно по паре имён из архива. **Проверять адреса без хэша в имени.** Файлы `_astro/*` продолжают отдаваться сетью доставки ещё год: они уезжают с `Cache-Control: immutable`, а `--delete` сносит их только с сервера. Это не остаток выкладки — на них не ссылается ни одна страница новой сборки, и адрес с чужим хэшем никому не достаётся. Проверка `_astro/*` на 404 поэтому даёт ложную тревогу, а не сигнал.

Затем: карта сайта отправляется в поисковую консоль, а через несколько дней просматривается отчёт об ошибках сканирования. Адреса, ранее отвечавшие успехом из-за подстановки главной страницы, теперь дают 404 — это ожидаемо; настоящие битые ссылки среди них требуют перенаправлений.

## Откат

Выложить сохранённый архив предыдущей сборки тем же порядком и сбросить кэш тех же постоянных адресов. Решение принимает владелец сайта; повод — недоступность страниц или потеря содержимого, а не отдельная косметическая разница.
