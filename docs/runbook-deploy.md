# lada.kiev.ua deploy

Сайт выкладывает только workflow `publish` (`.github/workflows/publish.yml`). Его запускает галочка «Опубликовать» в таблице цен или автор вручную: GitHub → Actions → publish → Run workflow, ветка `main`. Выкладки с машины автора и от root больше нет. Почему — ADR о единственном пути выкладки. Всё, что лежит в `main`, уходит на сайт при следующей публикации, в том числе от галочки Лады; незавершённая работа живёт в ветках.

## Manual run modes

| `mode` | Что делает |
|---|---|
| `publish` | суммы из таблицы → `src/data/prices.json` → гейты → выкладка → сброс кэша → проверки → commit в `main` → статус в таблицу |
| `dry-run` | то же на копии таблицы, без commit, выкладки, сброса кэша и записи в таблицу |
| `rebuild-sheet` | перестраивает обе таблицы из `prices.json`: строки, защиту, проверку ввода, подсветку |

`e2e` — полный e2e (три движка, 7–10 минут) вместо контракта цен и SEO. Ставь, когда в `main` пришла правка вёрстки, не прогнанная локально `npm run test:e2e` (ADR-027).

`allow_large_change` — ключи строк через запятую (столбец A таблицы, например `brows-lamination` или `full-body-massage-harmony@60`). Порог «больше чем вдвое» к ним не применяется. Галочка этот параметр передать не может.

Шаги публикации повторяют прежний ручной регламент:

- `rsync --delete` сносит файлы прошлой сборки, оставленные отвечали бы 200 и дублировали страницы в индексе;
- три `.htaccess` уезжают вместе с `dist/`;
- кэш Cloudflare сбрасывается для каждого постоянного адреса сборки, `_astro/*` не трогаются — у них хэш в имени;
- после выкладки идут проверки: 404 на битый адрес, наш `robots.txt` со строкой `Sitemap:`, `application/xml` у карты сайта, `lang="en"` у страницы ошибки раздела `/en/`. Последнюю локальный preview проверить не может: `ErrorDocument` внутри каталога он не реализует.

## Changing the price list

**Сумма** правится только в [таблице цен](https://docs.google.com/spreadsheets/d/1tX4kcULo9qupuYSd6uXH2DV3zVzRfHTQilQfB7TNvuM/edit): столбец «Сумма, грн», затем галочка `B1`. В `prices.json` сумму руками не меняй. Суммы принадлежат таблице, поэтому публикация остановится на конфликте. Если всё же поменял, `rebuild-sheet` примет сумму из репозитория.

**Структура** — добавить, убрать, переставить или переименовать позицию, поменять варианты или завести группу — меняется в репозитории:

1. Работай в ветке. Всё, что попало в `main`, уйдёт на сайт с ближайшей галочкой Лады.
2. `src/data/prices.json`: порядок в файле — это порядок на сайте и в таблице. `id` позиции и `count` варианта — ключ строки таблицы (`<id>` или `<id>@<count>`, у цены пастой — `<id>/sugar` или `<id>/sugar@<count>`). Поэтому переименование услуги меняет только `name`, а `id` остаётся. Новый ключ получает сумму из файла, а правка Лады под старым ключом пропадает. Цена пастой у позиции и `sugar: false` — тоже структура: после слияния нужен `mode: rebuild-sheet`, и строка пастой появится в таблице сразу за общей ценой позиции с подписью «сахар» в столбце «Вариант» ([content-model.md](specs/content-model.md) §Инварианты). Перенос текста в столбце «Вариант» вступает в силу при следующей перестройке; пока у позиций нет `sugar`, ради него перестройку не запускай.
3. Новая группа — строка в `src/data/price-groups.ts` (страница категории), в `src/i18n/tabs.ts` (вкладка главной), в `priceList.sections` словаря `src/i18n/ui.ts` на трёх языках и в `GROUP_CATEGORY` из `tests/support/site.ts` — намеренной копии связи групп для тестов. Группа, которую показывает подстраница, — ещё и в `groups` её записи в `src/data/subpage-registry.ts` и в `SERVICE_SUBPAGES` из `tests/support/site.ts`.
4. Изменил или убрал строку, которая есть в `tests/fixtures/legacy-content.json`, — поправь фикстуру тем же commit, иначе покраснеет `content-parity`. Число строк таблицы записано литералом в `scripts/prices/sheet-layout.test.mjs`: новая позиция или вариант меняет его.
5. Прогони все гейты локально, включая `npm run test:e2e`: публикация гоняет только контракт цен и SEO (ADR-027), а прайс меняет вёрстку вкладок.
6. Слей в `main` и сразу запусти `mode: rebuild-sheet`, затем `mode: publish` с `e2e`. Пока перестройка не прошла, галочка Лады останавливается на сверке структуры. Неопубликованные правки Лады перестройка сохраняет у тех ключей, которые остались.
7. Проверь новые позиции на сайте и строки в таблице.

Перед строками каждой группы в таблице стоит заголовок: русская подпись раздела из `priceList.sections` словаря `src/i18n/ui.ts`, тот же текст, что на сайте. По нему Лада различает одинаковые названия в разных группах, например «Глубокое бикини» у женской депиляции, мужского воска и триммера. Новая группа и новая подпись появляются в таблице только после `rebuild-sheet`. Группа без подписи в `ui.ts` или позиции группы, разнесённые по файлу, останавливают перестройку до записи в лист. `rebuild-sheet.mjs` загружает `ui.ts` через `--experimental-strip-types`, поэтому в словаре допустим только стираемый синтаксис TypeScript: без `enum` и `namespace`, относительный импорт — только с расширением `.ts`. Нарушение роняет `npm run test:unit` раньше, чем перестройку.

## Sheet status and what to do

| Статус в `C1` | Сайт | Действие |
|---|---|---|
| `опубликовано …` | обновлён | — |
| `опубликовано …, кроме N позиций` | обновлён без отклонённых | пометка в строке; если скачок настоящий — ручной запуск с `allow_large_change` |
| `ошибка, сайт не изменён` | прежний | лог запуска; сверка структуры или конфликт → `rebuild-sheet`, красный гейт → чинить в ветке |
| `ошибка после выкладки, сайт обновлён` | новый | лог: сброс кэша, проверки или push; повторный `publish` применит те же суммы. Откат — по решению владельца, не автоматически |
| `нет доступа к публикации` | прежний | токен истёк или отозван — новый PAT и `setup()` |
| `ошибка запуска` / зависшее `идёт с …` | прежний | лог запуска и письмо от скрипта таблицы |

## Rollback

Код: revert в `main` и ручной `publish`. Сборка воспроизводится из репозитория, архива на сервере нет.

Цена: исправить сумму в таблице и опубликовать. Revert commit бота бесполезен — таблица вернёт сумму. Возврат после разрешённого скачка — снова скачок, поэтому ручной запуск с `allow_large_change`.

## Access

- Таблица — на личном Google автора. Лада — редактор: без права выдавать доступ и снимать защиту.
- Скрипт таблицы — `apps-script/` в репозитории; вставить в редактор скрипта таблицы и выполнить `setup()` от имени автора.
- PAT для галочки — fine-grained `lada-prices-sheet-dispatch`, один репозиторий, `Actions: Read and write`, без срока действия: GitHub даёт не больше года, а ежегодную замену забывают. Если токен когда-нибудь получит срок, скрипт напишет автору за 14 дней до истечения. Новый токен → `setup()`.
- Google для workflow — Workload Identity Federation, без ключа. Сервер — пользователь `lada`, ключ ограничен `rrsync` корнем сайта. В `sshd_config` у `lada` блок `Match User lada`: вход только по ключу и `ForceCommand` на тот же `rrsync`, потому что вход по паролю на сервере включён, а у `lada` есть пароль Virtualmin. Убрать `lada` из `AllowUsers` — значит остановить выкладку. Cloudflare — токен Cache Purge. Секреты и переменные — environment `production`, только ветка `main`. Полный список — `specs/005-sheet-price-publishing/contracts/publish-workflow.md` §Job invariants.
