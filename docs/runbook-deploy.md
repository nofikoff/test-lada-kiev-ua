# Выкладка lada.kiev.ua

Сайт выкладывает только workflow `publish` (`.github/workflows/publish.yml`). Его запускает галочка «Опубликовать» в таблице цен или автор вручную: GitHub → Actions → publish → Run workflow, ветка `main`. Выкладки с машины автора и от root больше нет. Почему — ADR о единственном пути выкладки. Всё, что лежит в `main`, уходит на сайт при следующей публикации, в том числе от галочки Лады; незавершённая работа живёт в ветках.

## Переходный период

Пока environment `production` не настроен и первая публикация через workflow не прошла зелёной, выкладка идёт по прежнему ручному регламенту: `git show 0c6fbe8:docs/runbook-deploy.md` (последний commit `main` с ручной выкладкой, уже отправлен на GitHub). Этот раздел удаляется тем же commit, который отмечает первую зелёную публикацию (задача T035 пакета `specs/005-sheet-price-publishing`).

## Режимы ручного запуска

| `mode` | Что делает |
|---|---|
| `publish` | суммы из таблицы → `src/data/prices.json` → гейты → выкладка → сброс кэша → проверки → commit в `main` → статус в таблицу |
| `dry-run` | то же на копии таблицы, без commit, выкладки, сброса кэша и записи в таблицу |
| `rebuild-sheet` | перестраивает обе таблицы из `prices.json`: строки, защиту, проверку ввода, подсветку |

`allow_large_change` — ключи строк через запятую (столбец A таблицы, например `brows-lamination` или `full-body-massage-harmony@60`). Порог «больше чем вдвое» к ним не применяется. Галочка этот параметр передать не может.

Шаги публикации повторяют прежний ручной регламент:

- `rsync --delete` сносит файлы прошлой сборки, оставленные отвечали бы 200 и дублировали страницы в индексе;
- три `.htaccess` уезжают вместе с `dist/`;
- кэш Cloudflare сбрасывается для каждого постоянного адреса сборки, `_astro/*` не трогаются — у них хэш в имени;
- после выкладки идут проверки: 404 на битый адрес, наш `robots.txt` со строкой `Sitemap:`, `application/xml` у карты сайта, `lang="en"` у страницы ошибки раздела `/en/`. Последнюю локальный preview проверить не может: `ErrorDocument` внутри каталога он не реализует.

## Когда меняешь структуру прайса

Добавил, убрал, переставил или переименовал позицию в `prices.json` → после слияния в `main` запусти `mode: rebuild-sheet`. Без этого первая же публикация Лады остановится на сверке структуры. Сумму в `prices.json` руками не меняй: суммы принадлежат таблице, и публикация остановится на конфликте. Если поменял — `rebuild-sheet` примет сумму из репозитория.

## Статус в таблице и что делать

| Статус в `C1` | Сайт | Действие |
|---|---|---|
| `опубликовано …` | обновлён | — |
| `опубликовано …, кроме N позиций` | обновлён без отклонённых | пометка в строке; если скачок настоящий — ручной запуск с `allow_large_change` |
| `ошибка, сайт не изменён` | прежний | лог запуска; сверка структуры или конфликт → `rebuild-sheet`, красный гейт → чинить в ветке |
| `ошибка после выкладки, сайт обновлён` | новый | лог: сброс кэша, проверки или push; повторный `publish` применит те же суммы. Откат — по решению владельца, не автоматически |
| `нет доступа к публикации` | прежний | токен истёк или отозван — новый PAT и `setup()` |
| `ошибка запуска` / зависшее `идёт с …` | прежний | лог запуска и письмо от скрипта таблицы |

## Откат

Код: revert в `main` и ручной `publish`. Сборка воспроизводится из репозитория, архива на сервере нет.

Цена: исправить сумму в таблице и опубликовать. Revert commit бота бесполезен — таблица вернёт сумму. Возврат после разрешённого скачка — снова скачок, поэтому ручной запуск с `allow_large_change`.

## Доступы

- Таблица — на личном Google автора. Лада — редактор: без права выдавать доступ и снимать защиту.
- Скрипт таблицы — `apps-script/` в репозитории; вставить в редактор скрипта таблицы и выполнить `setup()` от имени автора.
- PAT для галочки — fine-grained, один репозиторий, `Actions: Read and write`. О сроке скрипт пишет за 14 дней. Новый токен → `setup()`.
- Google для workflow — Workload Identity Federation, без ключа. Сервер — пользователь `lada`, ключ ограничен `rrsync` корнем сайта. Cloudflare — токен Cache Purge. Секреты и переменные — environment `production`, только ветка `main`. Полный список — `specs/005-sheet-price-publishing/contracts/publish-workflow.md` §Job invariants.
