# ADR-026: Single CI deploy path

- **Related:** [ADR-025](adr-025-price-input-via-google-sheet.md) · [ADR-012](adr-012-tests-against-built-dist.md) · [docs/runbook-deploy.md](../runbook-deploy.md)

## Context

До 2026-10-12 сайт выкладывал автор со своей машины: `rsync` от root плюс сброс кэша Cloudflare руками. Публикация цен Ладой (ADR-025) требует выкладки без автора, а второй путь выкладки рядом с ручным разошёлся бы с ним в первую же правку регламента.

## Decision

Сайт выкладывает только workflow `publish` в GitHub Actions — по галочке в таблице цен или ручным запуском автора; содержимое `main` считается готовым к выкладке.

## Consequences

- Positive: выкладка без зелёных гейтов невозможна; `rsync` идёт под пользователем `lada` с ключом, ограниченным `rrsync` корнем сайта, — root-ключа в CI нет.
- Positive: сброс кэша берёт адреса из `dist/`, поэтому новая страница покрыта без правки списка.
- Negative: незавершённая работа не может лежать в `main` — её выложит следующая галочка Лады.
- Negative: архива сборки на сервере больше нет; откат — revert в `main` и ручной запуск, сборка воспроизводится из репозитория.
- **Rejected: оставить ручную выкладку автора рядом с workflow.** Два пути расходятся по шагам, и регламент перестаёт описывать то, что реально происходит на сервере.
- **Rejected: выкладка из CI от root, как раньше вручную.** Ключ в секретах репозитория давал бы root-shell на сервере.
- **Rejected: JSON-ключ service account для чтения таблицы.** Долгоживущий секрет; Workload Identity Federation выдаёт часовой токен только запускам из `main`.
