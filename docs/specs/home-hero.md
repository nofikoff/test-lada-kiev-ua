# Первый экран главной: портрет Лады

Реализация — `src/components/Hero.astro`, превью и JSON-LD — `src/components/SeoHead.astro`. Проверки — `tests/hero.spec.ts`, `tests/seo-contract.spec.ts`. Почему портрет стоит колонкой, а не фоном — [ADR-002](../adr/adr-002-hero-portrait-column-not-full-bleed.md). Принято в пакете 003, 2026-09-27.

## Разметка

- `h1` и текстовая колонка идут в DOM раньше портрета. На узком экране портрет ставит наверх CSS `order`, поэтому порядок заголовков и чтение диктором не меняются.
- Портрет — `<picture>` из записи `role: 'portrait'` коллекции `gallery`, с непустым `alt`, не декоративный. Загрузка с `priority`, без `loading="lazy"`.
- Ширины 480/768/1080/1440, `sizes="(min-width: 62rem) 40vw, 100vw"`. Lighthouse эмулирует Moto G с плотностью 1.75: на 412 px портрету нужно 721 px, и при ряде с 720w браузер брал 960w.
- Монограммы на первом экране нет.

## Раскладка

| Экран | Портрет | Текст | Гарантия |
|---|---|---|---|
| ≥ 62rem | Колонка справа, 4:5, высота до 86vh, ширина ≤ 720 CSS px — половина исходника 1440 при плотности 2x | Колонка слева на угле секции, без отдельной подложки | Лицо не пересекает текстовую колонку |
| < 62rem, портретная ориентация | Блок сверху, высота — остаток экрана после основной части текста (`--primary`), зажатый между 11rem и 62svh; лицо ниже фиксированной шапки | Под портретом: надзаголовок, `h1`, подзаголовок, кнопка звонка, затем описание и адрес | Кнопка звонка видна без прокрутки на 360×740 |
| Горизонтальная ориентация, малая высота | Сбоку, как на широком экране | Колонка слева | Портрет не добавляет высоты. Видимость кнопки не обещается: текстовая колонка не помещается в ~740×360 и без портрета |
| 1366×768 | Как ≥ 62rem | Как ≥ 62rem | Кнопка звонка видна без прокрутки |

Кнопка звонка на узком экране стоит раньше описания, потому что полная текстовая колонка на 360×740 выше остатка экрана: при любой высоте портрета кнопка уходила бы за край.

## Движение

- `wake` (1.8 с, 1 → 0) и `veil-breath` (0 ↔ 0.12) работают на сплошном слое угля над портретом, в пределах его рамки.
- Прозрачность `<img>` и его обёрток не анимируется никогда: иначе отрисовка портрета ждала бы окончания движения, а на телефоне портрет и есть элемент LCP.
- При `prefers-reduced-motion: reduce` действующих анимаций нет.

## Превью ссылок и JSON-LD

- `og:image` — результат `getImage` из портрета: 1200×630, JPEG, `fit: 'cover'`, `position` = `previewPosition` записи портрета. `og:image:width/height` берутся из результата. Вес ≤ 300 КБ.
- `previewPosition` — отдельное поле, потому что sharp принимает стороны (`top`, `center`, `bottom`), а не проценты CSS. На `50% 22%` он падает с `CouldNotTransformImage`, Astro понижает это до предупреждения, и сборка проходит без файла превью. Такой пропуск ловит `seo-contract.spec.ts`: файл отвечает 404.
- Файл превью ложится в `_astro/` с хэшем, который зависит от исходника и параметров кадра. Поэтому сбрасывать его в кэше CDN не нужно. Хэш стабилен между сборками на Astro 7.3.1, вес 56 КБ (замер 2026-09-27).
- `LocalBusiness.image` = `[logo, portrait]`, абсолютные адреса.

## Производительность: база от 2026-09-27

Lighthouse 12.8.2, мобильный профиль, `--throttling-method=simulate`, Chromium из Playwright, прогретый `npm run preview`, два прогона подряд:

| Адрес | Производительность | Доступность | LCP | CLS |
|---|---|---|---|---|
| `/` | 96 | 100 | 2.48 с | 0–0.008 |
| `/ru/` | 96 | 100 | 2.48–2.52 с | 0.003 |
| `/en/` | 99 | 100 | 2.02–2.11 с | 0 |

До портрета было 97 / 97 / 99 при LCP 2.3 / 2.3 / 1.8 с. На `/` и `/ru/` запаса до порога 2.5 с нет: следующее утяжеление первого экрана или начала ленты его перейдёт. Регрессия шла по каналу, а не по процессору: 80% LCP приходилось на задержку отрисовки, и килобайты картинок делили 1.6 Мбит/с симуляции с кириллическими шрифтами. Удержано рядами ширин и `quality={45}` у портрета — на 360×740 глазами неотличимо от штатного 50.

Любая правка первого экрана или первых карточек ленты — перемер:

```sh
npm run build && npm run preview   # PREVIEW_PORT из astro.config.mjs, не 4321 от astro dev
CHROME_PATH="$(node -e "console.log(require('playwright-core').chromium.executablePath())")" \
  npx -y lighthouse@12.8.2 http://localhost:4329/ --throttling-method=simulate \
  --only-categories=performance,accessibility,seo --chrome-flags="--headless=new" --output=json
```
