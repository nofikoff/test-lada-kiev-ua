# Routes and web server behaviour

Публичный контракт: нарушение любой строки — регрессия, даже если страница выглядит правильно. Правила сервера — `public/.htaccess`, `public/ru/.htaccess`, `public/en/.htaccess`; адреса строит `src/i18n/paths.ts`. Проверки — `tests/routes.spec.ts`, `tests/sitemap.spec.ts`, `tests/llms.spec.ts`, `tests/links.spec.ts`, `tests/build-output.spec.ts`. Почему адреса устроены так — [ADR-008](../adr/adr-008-urls-directory-format-latin-category-slugs.md). Выкладка — [runbook-deploy.md](../runbook-deploy.md). Принято в пакете 001, 2026-09-06.

## Canonical host

`https://www.lada.kiev.ua` — единственный хост, который сайт объявляет о себе: канонические адреса, языковые альтернативы, `og:url`, карта сайта, `llms.txt`. Apex отвечает 301 на `www`, поэтому адрес без `www` в разметке указывает на перенаправление. В коде хост объявлен один раз — `site` в `astro.config.mjs`. `tests/support/site.ts` держит свою копию намеренно: проверка, читающая константу реализации, проверяет только внутреннюю непротиворечивость.

Хост и схему приводит к канонической форме Cloudflare, а не Apache. Origin на apex и на `http` отвечает 200, поэтому в `.htaccess` правил хоста и схемы нет и не нужно:

| Запрос | Кто перенаправляет | Ответ |
|---|---|---|
| `http://lada.kiev.ua/<путь>`, `https://lada.kiev.ua/<путь>` | Single Redirect «Redirect from root to WWW»: `*://lada.kiev.ua/*` → `https://www.lada.kiev.ua/${2}`, query сохраняется | один 301 на `https://www.lada.kiev.ua/<путь>` |
| `http://www.lada.kiev.ua/<путь>` | Always Use HTTPS | 301 на `https://www.lada.kiev.ua/<путь>` |

- Шаблон правила начинается со `*://`, а не с `https://`. С `https://` запрос на `http://lada.kiev.ua/` сначала уходит через Always Use HTTPS на `https://lada.kiev.ua/` и до `www` доходит за два перенаправления. Redirect Rule срабатывает раньше Always Use HTTPS: в документации Cloudflare этот порядок не описан, он установлен замером 2026-10-11.
- `astro preview` этих перенаправлений не делает, поэтому прогон их не проверяет. Проверять на проде: `curl -sI http://lada.kiev.ua/ru/` ожидает один 301 на `https://www.lada.kiev.ua/ru/`.
- Настройки зоны меняются только в дашборде Cloudflare. У API-токена, которым сбрасывается кэш, на них прав нет.

## Route map

| Адрес | Статус |
|---|---|
| `/`, `/ru/`, `/en/` | 200 |
| `/<категория>/`, `/ru/<категория>/`, `/en/<категория>/` — `massage`, `depilation`, `permanent`, `beauty` | 200 |
| подстраницы услуг: `/depilation/sugaring/`, `/ru/depilation/sugaring/`, `/permanent/brows/`, `/ru/permanent/brows/` — [ADR-028](../adr/adr-028-commercial-service-subpages.md) | 200 |
| `/en/depilation/sugaring/`, `/en/permanent/brows/`, `/sugaring/`, `/powder-brows/` | 404: английских подстраниц нет, подстраница живёт только под своей категорией |
| раздел базы знаний, `<c>` — категория из `serviceCategories`, `<a>` — slug статьи: хаб `/guide/<c>/`, `/ru/guide/<c>/`, статья `/guide/<c>/<a>/`, `/ru/guide/<c>/<a>/` — [ADR-029](../adr/adr-029-knowledge-base-collection-links-from-seo-map.md) | 200, если есть файл `src/content/guide/<язык>/…` с этим путём |
| `/lada/`, `/ru/lada/` — страница эксперта | 200 |
| `/guide/`, `/ru/guide/` | 404: корня раздела нет, см. §Knowledge base |
| `/en/guide/…`, `/en/lada/`, хаб или статья без файла на этом языке | 404: маршрут адреса не собирает |
| `/ru`, `/en`, любой адрес страницы без слеша | 301 на форму со слешем. На `/ru` и `/en` стоят внешние ссылки. Исключение — `/guide` и `/ru/guide`: ожидается сразу 404, на проде не измерено (§Knowledge base) |
| `/sitemap-index.xml`, `/sitemap-0.xml` | 200, `application/xml` |
| `/robots.txt`, `/llms.txt` | 200 |
| любой другой | **404**, страница ошибки на языке раздела; без префикса — украинская |

- Канонический адрес и внутренние ссылки — сразу в форме со слешем: иначе канонический адрес указывает на перенаправление, а каждый внутренний переход стоит лишнего запроса.
- Правила подстановки главной страницы на любой адрес нет и не будет: до миграции оно отдавало 200 с главной на каждую опечатку и на `/sitemap.xml`, и поисковик считал их страницами-дублями.
- В карте сайта только адреса, отвечающие 200, и ни одной страницы ошибки. Языковых альтернатив — по числу языков страницы: три у главной и категорий, две (`uk-UA`, `ru-UA`) у подстраниц, хабов, статей и эксперта с версиями на двух языках; страница на одном языке альтернатив не получает (поведение `@astrojs/sitemap` 3.7.4). `x-default` и `lastmod` в карте сайта нет. Число страниц в тексте не пишется: оно менялось бы с каждой статьёй, а тест сверяет адреса, не прозу.
- Подстраница — запись реестра `serviceSubpages` в `src/data/subpage-registry.ts`: родительская категория, языки, группы прайса, способ цены. Маршрут под `en` не создаётся, поэтому английский адрес подстраницы не собирается и отвечает 404 по `ErrorDocument` раздела. 301 с адреса без слеша делает Apache; `astro preview` отвечает 200, и прогон проверяет `canonical` со слешем. Отвергнуто: подстраница как запись коллекции `services` с полем `parent` — пришлось бы ослабить правила «три файла на категорию» и «`category` из перечня»; файл маршрута на каждую подстраницу — одинаковые тела; свой компонент страницы подстраницы — копия `ServicePage.astro`, расходящаяся на первой правке.
- Новая подстраница — правка во всех местах сразу: запись в `serviceSubpages` и в `subpageRefs` (тот же файл), файл текста на каждый её язык в `src/content/subpages/`, копия в `SERVICE_SUBPAGES` и `QUERIES` из `tests/support/site.ts`, запись в `handedOver` из `tests/voice.spec.ts`, строка таблицы запросов в [page-head.md](page-head.md), строка карты в этом файле, адрес в `public/llms.txt`. Без любого из них прогон краснеет — по одному месту за раз.
- Новая статья базы знаний — правка в семи местах. Список хаба, список на `/lada/`, карта сайта и `hreflang` собираются сами: шаблоны и маршруты не правятся, это доказывает допустимый случай `npm run test:invalid-data`.
  1. Файл на каждый язык статьи — `src/content/guide/<язык>/<категория>/<slug>.md`, и хаб своего языка, если его ещё нет. Статья без хаба останавливает сборку.
  2. Строка страницы в §Pages и рёбра в §Links `docs/seo/map.md` — их пишет `/seo map`. Без строки или без ребра «хаб → статья» сборка останавливается. Без ребра «статья → хаб» или «статья → услуга» ссылки просто нет, и этого не ловит ничто.
  3. `tests/support/site.ts`: запись в `GUIDE_PAGES`, запрос статьи в `GUIDE_QUERIES` и этот же запрос в `HUB_FORBIDDEN` хаба её языка. Без первых двух краснеют `sitemap.spec.ts` и `voice.spec.ts`; пропуск запрета ничто не ловит.
  4. Строка запроса в [page-head.md](page-head.md) §Целевые запросы — только вычитка.
  5. Строка раздела `## Knowledge base` в `public/llms.txt` — краснеет `llms.spec.ts`.
  6. Строки §Sources и §Practice claims в [content-model.md](content-model.md) §Knowledge base — только вычитка.
  7. Имя собственное в новом анкоре карты, кроме «Київ» / «Киев», — в `properNouns` словаря `src/i18n/guide.ts`. Ловит только вычитка: `tests/links.spec.ts` сравнивает текст ссылки с анкором без регистра.

## Knowledge base

Хаб — файл `src/content/guide/<язык>/<категория>.md`, статья — `…/<категория>/<статья>.md`, эксперт — `src/content/expert/<язык>.md`; адрес повторяет путь файла, формат файлов — [content-model.md](content-model.md) §Knowledge base, решение — [ADR-029](../adr/adr-029-knowledge-base-collection-links-from-seo-map.md). Страница на одном языке получает `hreflang` на себя и `x-default` на себя — [page-head.md](page-head.md) §Языковые альтернативы.

### `/guide/` answers 404

Корня раздела нет: в карте его нет, а список без своего запроса размывает хабы. Сборка оставляет `dist/guide/` без `index.html`, а Apache отвечает на каталог без индекса кодом 403, не 404 (замер 2026-10-18: `curl -s -o /dev/null -w '%{http_code}' https://www.lada.kiev.ua/_astro/` → `403`). Поэтому `public/.htaccess` несёт `RedirectMatch 404 ^/guide/?$`, а `public/ru/.htaccess` — `^/ru/guide/?$`. Шаблон `/?$` отвечает 404 и на форму без слеша раньше, чем `DirectorySlash` успевает перенаправить её на каталог.

- `astro preview` не исполняет `.htaccess` и отвечает 404 на `/guide/` и без правила, поэтому локальный прогон о проде ничего не доказывает. Правило в `dist/.htaccess` и `dist/ru/.htaccess` проверяет `tests/build-output.spec.ts`; ответ сервера — шаг `smoke` в `publish.yml` после выкладки: 404 на `/guide/` и `/ru/guide/`, `lang="ru"` у второго.
- Формы без слеша — `/guide`, `/ru/guide` — не проверяет ни прогон, ни workflow. После первой выкладки раздела: `curl -s -o /dev/null -w '%{http_code}' https://www.lada.kiev.ua/guide` ожидает 404, не 301. Этот ответ на проде не измерен.
- `RedirectMatch` стоит вне `<IfModule mod_alias.c>` намеренно, в отличие от соседних блоков `.htaccess`. На проде модуль загружен, а каталогу сайта разрешено `AllowOverride All` (`httpd -M` → `alias_module`, root-SSH, 2026-10-18). Если модуля не станет, сайт ответит 500 и это заметят сразу; обёртка превратила бы ту же поломку в тихий 403 на `/guide/`.

### Directories without index

Каталог `dist/` без `index.html` отвечает на проде 403. `tests/build-output.spec.ts` сверяет такие каталоги со списком:

| Каталог | Чем закрыт |
|---|---|
| `_astro/` | ничем: файлы сборки, адрес не публичный, 403 допустим |
| `guide/`, `ru/guide/` | `RedirectMatch 404` в `.htaccess` своего раздела |

Промежуточный каталог хаба без индекса возникнуть не может: статья без хаба своего языка останавливает сборку. Новый каталог без индекса — например, маршрут `src/pages/x/y.astro` без `x/` — краснит тест: ему нужны строка в списке и правило 404.

### Links from the map

Ссылки страниц услуг и базы знаний берутся из `docs/seo/map.md` §Links, который пишет `/seo map`. Копии рёбер в коде нет: она разошлась бы с картой на первой правке.

Ребро `from → to (lang)` выводится на странице `from` языка `lang`, когда страница `to` этого языка собрана. Собранной страницу делает файл в контенте: колонка `status` и §Site карты не читаются, поэтому страница `planned` с файлом получает ссылку, а страница `published` без файла — нет. Ссылка — адрес `to` из §Pages со слешем. Текст — анкор ребра с поднятой первой буквой и восстановленным регистром имён собственных (`displayAnchor` и `properNouns` в `src/i18n/guide.ts`); после trim, схлопывания пробелов и нижнего регистра он равен анкору карты, и это сравнивает `tests/links.spec.ts`.

| Страница | Что выводится | Где |
|---|---|---|
| категория, подстраница | рёбра к страницам `hub`, `entity`, `question` | `MapLinks` сразу после `.service-copy`, вне `[data-service-copy]`; нет рёбер к собранным страницам — нет блока, тексты категорий не правятся |
| хаб | список всех статей своей категории и языка, текст — анкор ребра «хаб → статья»; порядок — `published` по убыванию, затем `heading` | тело хаба после вступления |
| хаб | ребро к услуге: `MapLinks` с `toKinds={['service']}`; статью блок второй раз не выводит | после списка |
| статья | все рёбра: к хабу, к услуге, к соседним статьям | `MapLinks` после текста |
| статья | подпись из `signatureName` и `signatureRole` в `src/content/about/<язык>.md`, ведёт на эксперта своего языка | под `<h1>`, с датами публикации и правки |
| эксперт | список всех статей языка, текст — `heading`, с датой публикации | после текста |

- Ребро «хаб → статья» есть у каждой статьи: без него сборка останавливается, поэтому хаб перечисляет все статьи с анкором карты. Рёбра «статья → хаб», «статья → услуга» и «хаб → услуга» сборка не требует. Для статьи пилота их держат литералы `PILOT_EDGES` в `tests/support/site.ts`, независимые от карты: общее правило `tests/links.spec.ts` читает карту, и ребро, удалённое из неё, убрало бы ссылку молча.
- Ссылка, которую автор ставит в теле Markdown, ведёт на собранный адрес в форме со слешем. `/depilation` указывает на перенаправление, и `tests/links.spec.ts` его не принимает.
- Шапка сайта пункта раздела не получает.

### llms.txt

Раздел `## Knowledge base` стоит между `## Pages` и `## Services`: абсолютные адреса хаба, статьи и эксперта на uk и ru, к каждому английское описание в одну строку. Новая статья — новая строка раздела. Вводная часть не считает страницы и не обещает прайс везде: она называет языки по видам страниц, а прайс — у страниц услуг, потому что у хаба, статьи и эксперта его нет. Число в тексте менялось бы с каждой статьёй, а `tests/llms.spec.ts` проверяет адреса, не прозу, и устаревшее число прошло бы молча.

## Error page per section

`ErrorDocument 404` объявлен в каждом из трёх `.htaccess`: корневой — украинская, `ru/` и `en/` перекрывают его своими. `astro preview` эту директиву не реализует и отдаёт один корневой файл, поэтому язык страницы ошибки по разделу проверяется только на проде — [runbook-deploy.md](../runbook-deploy.md) §После выкладки.

## Caching

| Что | Срок | Почему |
|---|---|---|
| `_astro/*` — css, js, woff2, avif, webp, jpg | год, `immutable` | имя содержит хэш содержимого, обновление приходит новым именем |
| HTML | 5 минут, `must-revalidate` | без перепроверки вернувшийся посетитель получает страницу со ссылками на удалённые файлы прошлой сборки |
| `png` в `public/` | сутки | постоянный адрес, кэшируется соцсетями |
| xml, txt | час | |

Cloudflare перед сервером кэширует статику четыре часа и не кэширует HTML (замер 2026-09-06), поэтому постоянные адреса после выкладки сбрасываются вручную.

## Contact consistency

Адрес, телефон и часы работы совпадают в разметке страниц, в JSON-LD и в `public/llms.txt`. `llms.txt` пишется руками и расходится с остальными молча; держит `tests/llms.spec.ts`.
