# Routes and web server behaviour

Публичный контракт: нарушение любой строки — регрессия, даже если страница выглядит правильно. Правила сервера — `public/.htaccess`, `public/ru/.htaccess`, `public/en/.htaccess`; адреса строит `src/i18n/paths.ts`. Проверки — `tests/routes.spec.ts`, `tests/sitemap.spec.ts`, `tests/llms.spec.ts`. Почему адреса устроены так — [ADR-008](../adr/adr-008-urls-directory-format-latin-category-slugs.md). Выкладка — [runbook-deploy.md](../runbook-deploy.md). Принято в пакете 001, 2026-09-06.

## Canonical host

`https://www.lada.kiev.ua` — единственный хост, который сайт объявляет о себе: канонические адреса, языковые альтернативы, `og:url`, карта сайта, `llms.txt`. Apex отвечает 301 на `www`, поэтому адрес без `www` в разметке указывает на перенаправление. В коде хост объявлен один раз — `site` в `astro.config.mjs`. `tests/support/site.ts` держит свою копию намеренно: проверка, читающая константу реализации, проверяет только внутреннюю непротиворечивость.

Хост и схему приводит к канонической форме Cloudflare, а не Apache. Origin на apex и на `http` отвечает 200, поэтому в `.htaccess` правил хоста и схемы нет и не нужно:

| Запрос | Кто перенаправляет | Ответ |
|---|---|---|
| `http://lada.kiev.ua/<путь>`, `https://lada.kiev.ua/<путь>` | Single Redirect «Redirect from root to WWW»: `*://lada.kiev.ua/*` → `https://www.lada.kiev.ua/${2}`, query сохраняется | один 301 на `https://www.lada.kiev.ua/<путь>` |
| `http://www.lada.kiev.ua/<путь>` | Always Use HTTPS | 301 на `https://www.lada.kiev.ua/<путь>` |

- Шаблон правила начинается со `*://`, а не с `https://`. С `https://` запрос на `http://lada.kiev.ua/` сначала уходит через Always Use HTTPS на `https://lada.kiev.ua/` и до `www` доходит за два перенаправления. Redirect Rule срабатывает раньше Always Use HTTPS: в документации Cloudflare этот порядок не описан, он установлен замером 2026-10-11.
- `astro preview` этих перенаправлений не делает, поэтому прогон их не проверяет. Проверять на проде: `curl -sI http://lada.kiev.ua/ru/` ожидает один 301 на `https://www.lada.kiev.ua/ru/`.
- Настройки зоны меняются только в дашборде Cloudflare. У API-токена, которым сбрасывается кэш, на них прав нет.

## Route map

| Адрес | Статус |
|---|---|
| `/`, `/ru/`, `/en/` | 200 |
| `/<категория>/`, `/ru/<категория>/`, `/en/<категория>/` — `massage`, `depilation`, `permanent`, `beauty` | 200 |
| подстраницы услуг: `/depilation/sugaring/`, `/ru/depilation/sugaring/`, `/permanent/brows/`, `/ru/permanent/brows/` — [ADR-028](../adr/adr-028-commercial-service-subpages.md) | 200 |
| `/en/depilation/sugaring/`, `/en/permanent/brows/`, `/sugaring/`, `/powder-brows/` | 404: английских подстраниц нет, подстраница живёт только под своей категорией |
| `/ru`, `/en`, любой адрес страницы без слеша | 301 на форму со слешем. На `/ru` и `/en` стоят внешние ссылки |
| `/sitemap-index.xml`, `/sitemap-0.xml` | 200, `application/xml` |
| `/robots.txt`, `/llms.txt` | 200 |
| любой другой | **404**, страница ошибки на языке раздела; без префикса — украинская |

- Канонический адрес и внутренние ссылки — сразу в форме со слешем: иначе канонический адрес указывает на перенаправление, а каждый внутренний переход стоит лишнего запроса.
- Правила подстановки главной страницы на любой адрес нет и не будет: до миграции оно отдавало 200 с главной на каждую опечатку и на `/sitemap.xml`, и поисковик считал их страницами-дублями.
- В карте сайта только адреса, отвечающие 200: девятнадцать страниц. У главной и категорий три языковые альтернативы, у подстраниц две — `uk-UA` и `ru-UA`. Страниц ошибки в ней нет.
- Подстраница — запись реестра `serviceSubpages` в `src/data/subpage-registry.ts`: родительская категория, языки, группы прайса, способ цены. Маршрут под `en` не создаётся, поэтому английский адрес подстраницы не собирается и отвечает 404 по `ErrorDocument` раздела. 301 с адреса без слеша делает Apache; `astro preview` отвечает 200, и прогон проверяет `canonical` со слешем. Отвергнуто: подстраница как запись коллекции `services` с полем `parent` — пришлось бы ослабить правила «три файла на категорию» и «`category` из перечня»; файл маршрута на каждую подстраницу — одинаковые тела; свой компонент страницы подстраницы — копия `ServicePage.astro`, расходящаяся на первой правке.
- Новая подстраница — правка во всех местах сразу: запись в `serviceSubpages` и в `subpageRefs` (тот же файл), файл текста на каждый её язык в `src/content/subpages/`, копия в `SERVICE_SUBPAGES` и `QUERIES` из `tests/support/site.ts`, запись в `handedOver` из `tests/voice.spec.ts`, строка таблицы запросов в [page-head.md](page-head.md), строка карты в этом файле, адрес в `public/llms.txt`. Без любого из них прогон краснеет — по одному месту за раз.
- Новая статья базы знаний — правка в семи местах (FR-016 пакета 007). Список хаба, список на `/lada/`, карта сайта и `hreflang` собираются сами: шаблоны и маршруты не правятся, это доказывает допустимый случай `npm run test:invalid-data`.
  1. Файл на каждый язык статьи — `src/content/guide/<язык>/<категория>/<slug>.md`, и хаб своего языка, если его ещё нет. Статья без хаба останавливает сборку.
  2. Строка страницы в §Pages и рёбра в §Links `docs/seo/map.md` — их пишет `/seo map`. Без строки или без ребра «хаб → статья» сборка останавливается. Без ребра «статья → хаб» или «статья → услуга» ссылки просто нет, и этого не ловит ничто.
  3. `tests/support/site.ts`: запись в `GUIDE_PAGES`, запрос статьи в `GUIDE_QUERIES` и этот же запрос в `HUB_FORBIDDEN` хаба её языка. Без первых двух краснеют `sitemap.spec.ts` и `voice.spec.ts`; пропуск запрета ничто не ловит.
  4. Строка запроса в [page-head.md](page-head.md) §Целевые запросы — только вычитка.
  5. Строка раздела `## Knowledge base` в `public/llms.txt` — краснеет `llms.spec.ts`.
  6. Строки §Sources и §Practice claims в [content-model.md](content-model.md) §Knowledge base — только вычитка.
  7. Имя собственное в новом анкоре карты, кроме «Київ» / «Киев», — в `properNouns` словаря `src/i18n/guide.ts`. Ловит только вычитка: `tests/links.spec.ts` сравнивает текст ссылки с анкором без регистра.

## Error page per section

`ErrorDocument 404` объявлен в каждом из трёх `.htaccess`: корневой — украинская, `ru/` и `en/` перекрывают его своими. `astro preview` эту директиву не реализует и отдаёт один корневой файл, поэтому язык страницы ошибки по разделу проверяется только на проде — [runbook-deploy.md](../runbook-deploy.md) §После выкладки.

## Caching

| Что | Срок | Почему |
|---|---|---|
| `_astro/*` — css, js, woff2, avif, webp, jpg | год, `immutable` | имя содержит хэш содержимого, обновление приходит новым именем |
| HTML | 5 минут, `must-revalidate` | без перепроверки вернувшийся посетитель получает страницу со ссылками на удалённые файлы прошлой сборки |
| `png` в `public/` | сутки | постоянный адрес, кэшируется соцсетями |
| xml, txt | час | |

Cloudflare перед сервером кэширует статику четыре часа и не кэширует HTML (замер 2026-09-06), поэтому постоянные адреса после выкладки сбрасываются вручную.

## Contact consistency

Адрес, телефон и часы работы совпадают в разметке страниц, в JSON-LD и в `public/llms.txt`. `llms.txt` пишется руками и расходится с остальными молча; держит `tests/llms.spec.ts`.
